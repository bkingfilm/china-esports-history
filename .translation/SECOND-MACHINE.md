# 第二台机器部署清单（只跑翻译线）

翻译线是唯一适合分到第二台机器的班：它不需要任何平台登录态、不抢浏览器和剪贴板和 GPU，只读写文件加 git。

## ⛔ 绝对不要做的三件事

1. **不要把任何代发班复制到 B 机。** X、Threads、小红书、抖音、微博、Reddit、V2EX 的引擎一律留在主机。两台机器同时操作同一个社媒账号是异地并发登录，风控风险远大于产能收益。
2. **不要两台机器都跑同一条翻译线。** B 机的韩语线跑通并入库一篇之后，才把主机上的 `esports-history-translate-ko` 设为 `enabled=false`。顺序反了会有一夜空窗，顺序对了不会双跑（判定靠 `docs/ko/` 目录内容，见 [ORDER.md](ORDER.md)）。
3. **不要在 B 机上改 `docs/en/`。** 语言目录隔离是两机零冲突的基础：主机只写 `docs/en/`，B 机只写 `docs/ko/`。两边即使同时提交也只是改不同文件。

## 部署步骤

1. **登录同一个 Claude 账号**，装 Claude Code 桌面端。定时任务存在本机 `~/.claude/scheduled-tasks/`，不跟账号同步，所以 B 机默认是干净的，不会自动跑主机的任何班。
2. **clone 仓库**。路径建议与主机一致（`G:\claude code\china-esports-history`），这样任务文件里的路径不用改。若 B 机没有 G 盘，clone 到别处并把任务文件里所有出现的仓库路径一并替换。
3. **配 git 身份与推送凭据**：仓库 local 配 `user.name=bkingfilm`、`user.email=chozuihei@gmail.com`，并确认能 push（HTTPS token 或 SSH key）。**先手动 push 一个空 commit 验证通，再建定时任务**，否则译文会翻好但推不上去。
4. **装 gh CLI 并认证**（可选，用于查插队 Issue；未认证会报 HTTP 401，翻译班有 WebFetch 兜底，不阻塞）。
5. **只建一个定时任务**：把主机 `~/.claude/scheduled-tasks/esports-history-translate-ko/` 整个目录复制到 B 机同位置。cron 保持 `35 3,5 * * *`（03:35 / 05:35 两档）。
6. **B 机要整夜开机**，深夜档才准时。任务里已有防洪：迟到超过 2 小时自动作废本档只记日志，所以 B 机白天关机也不会造成开机后的补跑洪水。
7. **跑通验证**：手动触发一次，确认三件事 —— `docs/ko/` 下出现新文件、`docs/ko/index.md` 被更新、commit 成功 push 到远端。三件都对了，再回主机停掉韩语线。

## 产能预期要摆正

**配额是按账号算的，两台机器不等于双倍产能。** 双机的真实收益是摆脱单机开关机时间的约束：B 机专门整夜开着跑深夜档，主机白天正常用、晚上照常关。如果期待的是产能翻倍，先降低期待。

## 扩展到第三条语言线时

同样的模式：一台一语言、语言目录隔离、顺序表统一在 [ORDER.md](ORDER.md)。不要让两台机器共享同一条线的排班状态，也不要把排班状态写回任何单机本地文件。
